Новых результатов из тех старых игр, где в момент урока отчёт не был сохранён, создать задним числом нельзя.

## Серверный приём: подготовлено, но НЕ развёрнуто
`integration/ReliableGameInbox.gs` — дополнительный Apps Script файл с постоянным накоплением входящих игровых сообщений. Он записывает входящее событие в Script Properties до ответа Telegram и затем обрабатывает пачками по таймеру. После вызова обработчика проверяет по ID ученика, игры и попытки фактическое наличие строки в целевой таблице. Если строка не появилась, сообщение остаётся в очереди для повторной обработки. Не подменяет `QuizBot.gs` без его точечной правки.

### Точное место подключения (только после сравнения с текущим кодом!)
В действующем Apps Script бота:
1. Создать файл `ReliableGameInbox.gs` и вставить одноимённый файл из GitHub.
2. В **`QuizBot.gs`**, функция **`doPost(e)`**, после проверки `QUIZ_WEBHOOK_KEY` заменить только прежний прямой вызов

```javascript
e4Handle_(JSON.parse(e.postData.contents));
```

на

```javascript
const incoming = JSON.parse(e.postData.contents);
if (incoming.message && incoming.message.web_app_data)
  e4GameInboxAccept_(incoming);
else
  e4Handle_(incoming);
```

3. В Apps Script выбрать функцию `e4GameInboxInstallTrigger_`, выполнить один раз, разрешить работу по расписанию. Она создаёт триггер `e4GameInboxDrain_` раз в минуту.
4. **Развернуть → Управление развёртываниями → Изменить → Новая версия → Развернуть.** Не создавать другой webhook URL.
5. Выполнить `e4GameInboxHealth_` и убедиться, что установлен триггер и в очереди нет необработанных событий. Во время теста с 5–15 одновременными попытками проверить запись всех уникальных `attemptId`, ответы бота, повторную отправку и отсутствие двойных очков.

Не удалять прежние обработчики `e4GameResult_`, `e4Ege12SkillResult_`, `e4SaveGameSkills_`, `textoriaRebuild`: приёмная очередь передаёт данные существующему обработчику. После включения ответ бота о сохранении может появляться с задержкой примерно до минуты.

**Ограничения**: Script Properties имеют квоты и не заменяют внешнюю промышленную очередь. Нужны контроль переполнения, мониторинг и испытание на реальных Telegram Mini App. Проверка сохранения читает целевую таблицу, поэтому нагрузку и время выполнения тоже необходимо проверить. Не включать эту архитектуру без просмотра актуального `QuizBot.gs`, особенно если в нём уже действует собственный механизм входящей очереди, и без тестовой отправки. Нельзя считать новую серверную схему действующей до развёртывания.

## Текстория № 12 — две отдельные исправления в действующем Apps Script
В файле интерфейса `TextoriaWeb.html` / `TextoriaWeb` в массиве `allGames` сейчас было:

```javascript
{n:12,t:'Окончания глаголов и суффиксы причастий',items:[]},
```

Заменить на:

```javascript
{n:12,t:'Окончания глаголов и суффиксы причастий',
 items:[{t:'Целую, милая',gameId:'ege12-celuyu-milaya'}]},
```

В файле, содержащем **`function textoriaGame_(id)`**, внутри `aliases` добавить:

```javascript
'ege12-celuyu-milaya': 12,
```

Это требуется для **учёта в рейтинге**, а не только для видимости ссылки. При запуске из Текстории путь должен быть:
`https://t.me/russian11_island_bot?start=textoria_ege12-celuyu-milaya` → обработчик `textoriaHandleTelegramStart_` → **Reply Keyboard Mini App** → `sendData` → бот → таблица «Тренажёры — результаты» → пересчёт Текстории. Открытие обычной веб-ссылки внутри Текстории само по себе не обеспечивает Telegram `sendData`.

**Текущая версия Textoria Apps Script не открыта для записи через подключённые инструменты. Изменения в этом пункте ещё НЕ развёрнуты.**
