# Правила разработки игровых тренажёров · 11 «К»

## Назначение
Игры открываются как Telegram Mini Apps на iPhone и Android. Они не должны требовать скачивания HTML. Отдельные тренажёры регистрируются в листе «Тренажёры» и записывают попытки в «Тренажёры — результаты».

## Обязательно: игровой экран без прокрутки
- Каждый игровой ход занимает **один экран**: вопрос, варианты ответа и основное действие видны одновременно.
- Область игры ограничена высотой `100dvh` (с резервным `100vh`); учитываются `env(safe-area-inset-top)` и `env(safe-area-inset-bottom)`.
- Убираем большие шапки, пояснения и декоративные отступы из активного режима. Инструкции показываются на отдельном стартовом экране.
- **Не уменьшаем текст до нечитаемого размера.** Для длинного материала используем отдельный экран чтения/«Развернуть условие» с явным возвращением к выбору ответа — не длинную страницу, которую нужно пролистывать ради кнопок.
- Одна задача за экран; сетка вариантов адаптируется к ширине и высоте. Управление доступно без прокрутки и без точного перетаскивания на сенсорном экране.
- Кнопки и зоны касания достаточного размера (ориентир ≥44 CSS px), без случайных срабатываний и перекрытий.
- При маленькой высоте раскладка уплотняется медиазапросами. Прогресс сворачивается в короткую строку.
- Проверяем режимы 320×568, 375×667, 390×844 и 430×932, а также изменение ориентации и размеры шрифта iOS.
- Для экранов результатов и разбора ошибок **прокрутка допустима**, если весь подробный материал не помещается. Запрет относится к активному игровому ходу.

## Связь с Telegram
- Мини-приложение запускается **через Reply Keyboard кнопку `web_app`** внутри личного чата бота, чтобы можно было вызвать `Telegram.WebApp.sendData`.
- Идентификатор ученика берётся **из подписанного Telegram update на стороне Apps Script**, а не из поля, которое HTML присылает самостоятельно.
- Формат завершения: `{v:1,type:"game_result",gameId:"TR8_01",attemptId:"uuid",correct:12,total:15,errors:{"Управление":2,"Причастный оборот":1}}`.
- `gameId` должен в точности совпадать со столбцом A листа «Тренажёры».
- Отправляем результат **после окончания игры**, не при открытии; отдельный `attemptId` на каждую попытку; повторные сообщения с тем же ID не должны дублировать запись.
- Разбивка `errors` по содержательным правилам обязательна для игр, предназначенных для карты навыков. Нулевое число ошибок представляем `{}`.
- Результаты из HTML — **учебная статистика, а не защищённые экзаменационные баллы**: клиентские данные можно модифицировать. Для контрольных нужна проверка результатов на сервере.

## Публикация
- Исходники и игра доступны по HTTPS на GitHub Pages.
- Каждую новую игру помещаем в отдельный каталог `games/<game-id>/index.html`, не перезаписывая корневую пилотную игру.
- В таблице «Тренажёры» статус **«В подготовке»** до проверки внутри Telegram на iPhone; «Готов» только после подтверждения учителем.
- Токены бота, приватные данные учеников и API-ключи **никогда** не размещать в публичном репозитории.
- Проверяем один полный цикл: вход → прохождение → отправка результата → запись в Google Sheets → кнопка «📊 Моя статистика» → сводка по игре.
